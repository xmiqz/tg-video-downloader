# 大屏结果区铺满宽度（T61b 三次修复）

## 起因

- 上一版（`29f3c4e`）只在 `≥1280px` 放开 760px 窄带，实际终端 CSS 宽度常落在
  **1024–1279**（1920 物理屏 125%–150% 缩放、窗口非最大化），仍按 760px 渲染，
  右侧一大片空白（`before-1152x900.png`）。
- 第二版（`5efddea`）把下界降到 1024 并改成自适应多列网格，但用户裁决：
  **每行不加列**，大屏要单列铺满宽度、尽可能显示内容、不留白。

## 改动（只动布局，不动 DOM / RPC / 移动端）

`web/css/views/new.css`（≥1024 段）：

- `.nw-wiz:has(.nw-list) { max-width: none }`：含结果列表的向导取消 760px 上限；
- 结果列表保持默认单列（移除 `display:grid` 与 `auto-fill` 列模板），
  仅保留 `max-height: 52vh` 内滚；
- `.nw-row` 三段式模板 `auto minmax(0,1fr) auto`：信息列吃掉整行剩余宽度，
  名称/拟命名/摘要随行宽显示更多内容，体积与来源标签贴容器右缘；
- 工具条 `nowrap` + 筛选框 `flex:1`（≤560px）+ 批量按钮右对齐；
- `<1024` 全部断点一行未改。

`web/js/router.js`（1 处，防"改了看不出区别"）：

- 视图 CSS 由 `css/views/x.css` 改为 `css/views/x.css?v=<页面加载时间戳>`。
  升级后浏览器不会再复用旧 CSS；同一次页面加载内 URL 稳定，不影响缓存命中率。
