# v2.6.2 发布说明

> 基于 v2.6.1 的并发硬化：确保下载中改名不会因为保存时序再次出现“JSON 名称与磁盘文件不一致”。

## 修复

- 改名/恢复后的 live 会话同步改为投递到会话事件循环执行，并立即强制回写会话快照；最后一次落盘一定携带新名称。
- 覆盖任务标题与条目名称两条路径；与下载线程的周期性保存串行化，不再存在“旧快照最后写回”的窗口。

## 兼容性

- 任务 JSON、数据目录、导出包格式、Docker 卷名与端口不变。
- `compose.yaml` 默认镜像指向 `v2.6.2`；仍支持 `TGVD_DATA_DIR` 绑定宿主机目录。

## 验证

- 后端测试：`437 passed, 1 skipped`（`pytest -q tests`）。
- 前端测试：`189 pass, 0 fail`（`node --test "tests/js/*.test.mjs"`）。
- 桌面 / CLI：全平台构建通过（Windows x64/ARM64、Linux x64/ARM64、macOS x64/arm64）。
- Docker：`linux/amd64` 与 `linux/arm64` 构建验证通过；GHCR `v2.6.2` manifest 含两种架构。
- 在线 YAML 部署测试：拉取 `v2.6.2` 的 `compose.yaml` 启动成功，`/healthz` 返回 `v2.6.2` 与 7 位构建 SHA。
