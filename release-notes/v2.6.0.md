# v2.6.0 发布说明

## 重点

- 新增 Telegram 扫码登录，桌面端与 NAS / 浏览器首次设置页均可使用。
- 小号添加同样支持扫码登录；二维码会话与主号相互独立。
- 扫码登录不依赖短信、邮箱或 Telegram App 推送；手机 Telegram 已登录时扫码确认即可。
- 手机号验证码仍可用，但不再写死为“Telegram App”；页面显示 Telegram 返回的真实投递渠道提示。
- Telegram 两步验证流程复用现有密码步。

## 兼容性

- 任务 JSON、数据目录、导出包格式、Docker 卷名与端口不变。
- 新增 `segno` 依赖用于生成 SVG 二维码；二维码 token 不写盘、不写日志。
- RPC 方法集合新增主号扫码 5 个与小号扫码 4 个方法，总数从 57 变为 66。
- 二维码会话只在进程内存保存，刷新页面或服务重启后需要重新生成。

## 验证

- 后端测试：`379 passed, 3 warnings`（`pytest -q tests`）。
- 前端测试：`188 pass, 0 fail`（`node --test "tests/js/*.test.mjs"`）。
- 本分支未构建正式桌面包或 Docker 镜像；正式发布前仍需在 CI 完成 amd64 / arm64 构建校验。

## 已修复的验收问题

- 二维码容器在注入 SVG 后仍为 `hidden`，页面只显示“刷新二维码”按钮；现在会显式显示，且刷新按钮位于二维码步骤内。
- 二维码登录曾写入独立的 `tg_session-qr` 会话文件，扫码成功但重启后登录态丢失；现在与主会话共用同一文件。
- 新浏览器在 `/login` 页触发 RPC 401 时会回到管理员登录表单，不再整页重载造成初始化循环。
