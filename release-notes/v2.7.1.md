# v2.7.1 发布说明

## 概览

v2.7.1 是稳定性与错误体验补丁版本：统一底层异常的用户文案，补充分片停滞退避和任务级自动恢复，并在下载页显示任务健康状态。扫新和搜索遇到部分失败时会保留已有结果。任务 JSON 必需字段、数据目录与端口保持不变。

## 稳定性与错误体验

- `ShardResetExhausted`、`Request was unsuccessful 6 time(s)` 与 Telegram `ServerError` 不再暴露原始类名或英文错误；GUI、TUI、RPC 和浏览器统一显示友好原因、自动重试状态与已下载进度保留提示。
- 分片停滞按连续 1 / 2 / 3 次分别退避 1 / 3 / 6 秒并加入抖动；收到新字节后停滞计数清零。
- 新增任务级熔断：120 秒内 3 次可重试失败后进入自动恢复，依次等待 20 / 45 / 90 秒，最多 3 轮；期间失败的任务进入等待队列，成功后清空状态。
- 扫新和搜索的部分失败不再丢弃整批结果：已找到的条目会保留，并提示保留数量与错误原因。

## 界面

- 下载页新增任务级健康条，展示自动恢复轮次、下次恢复倒计时与失败原因；三轮恢复失败后提示手动重试。
- 底层技术信息移到折叠区域，默认只显示友好错误和建议操作。

## 升级说明

- 固定版本镜像：`ghcr.io/xmiqz/tg-video-downloader:v2.7.1`。
- 从 v2.7.0 升级时拉取新镜像并重新创建容器，例如执行 `docker compose pull && docker compose up -d`；如用 `.env` 覆盖了 `TGVD_IMAGE`，需先将镜像 tag 改为 `v2.7.1`。
- 数据目录、导出包格式、容器卷名与端口不变，Web 端口仍为 `8787`；无需迁移或删除用户数据卷。
- 升级前照常备份 `/data`；命名卷与 bind mount 的具体命令见 [备份 / 升级 / 回滚手册](../docs/nas-backup-restore.md)。

## 兼容性

- 任务 JSON 必需字段、数据目录、导出包格式、容器卷名与 `10001:10001` 运行用户不变。
- `compose.yaml` 默认镜像指向 `v2.7.1`，继续支持 `TGVD_DATA_DIR` 绑定宿主机目录；宿主机 bind mount 仍需预先设置为 `10001:10001`。
- 未引入需要迁移或删除用户数据卷的升级步骤。
